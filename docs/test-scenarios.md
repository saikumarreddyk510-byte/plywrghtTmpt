## Happy Path Scenarios (TC-001 to TC-099)

### TC-001: Valid credentials log the user in and reach the dashboard
**Category**: Happy Path
**Priority**: P0
**Preconditions**: A registered account exists (`playwright/testdata/users.json` → `loginUser`)
**Steps**:
1. Navigate to `/client/#/auth/login`
2. Fill Email with a valid registered email
3. Fill Password with the matching password
4. Click the login submit control
**Expected Results**:
- URL becomes `/client/#/dashboard/dash`
- Page title remains "Let's Shop"
**Business Rule**: Correct credentials → redirect to dashboard
**Suggested Layer**: E2E

## Negative Scenarios (TC-300 to TC-399)

### TC-301: Invalid credentials show an error and do not navigate away
**Category**: Negative
**Priority**: P0
**Preconditions**: None (no account needs to exist)
**Steps**:
1. Navigate to `/client/#/auth/login`
2. Fill Email with a non-existent address
3. Fill Password with an incorrect value
4. Click the login submit control
**Expected Results**:
- A `.toast-message` becomes visible containing "Incorrect email or password."
- URL remains `/client/#/auth/login` (no redirect to dashboard)
**Business Rule**: Wrong credentials → toast error, no navigation away from login
**Suggested Layer**: E2E
